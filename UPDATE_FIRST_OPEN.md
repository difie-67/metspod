# Исправление открытия лота из объявления

Версия: `2026-10-03_listing-first-open`.

## Установка

Замените файлы из архива исправлений в корне проекта с сохранением путей:

- `src/bot.ts`
- `src/index.ts`
- `src/listings.ts`
- `src/listing-link.ts` (новый файл)
- `src/version.ts`
- `package.json`
- `BUILD_VERSION.txt`
- `tests/listing-link.spec.ts` (новый тест)
- `tests/startup-link.spec.ts` (новый тест)
- `UPDATE_FIRST_OPEN.md` (эта инструкция)

Пересоберите и перезапустите автогаранта в Railway. В логе запуска должна появиться версия `2026-10-03_listing-first-open`. Используйте один запущенный polling-процесс бота с этим токеном. Базу SQLite и постоянный том сохраняйте: существующие лоты находятся именно там. Второй проект (предложку) обновлять для этого исправления не требуется.

## Что изменено

- Приём Telegram-сообщений начинается без ожидания проверки TON и настройки меню Telegram.
- Активный лот читается сразу из SQLite.
- Если лот ещё не зарегистрирован или находится в `pending`, один `/start lot_…` автоматически повторяет поиск каждые 250 мс в течение не более 8 секунд. При активации карточка отправляется в рамках исходного запроса.
- Переход по `/start` закрывает предыдущий режим ввода кошелька/сделки.
- Ссылка не создаёт сделку, не снимает бронь и не активирует лот. Создание запроса по-прежнему требует кнопки «Оформить сделку», продажа — согласия продавца.

## Логи

Логи доступны в Railway и существующем файле `runtime.log` рядом с базой. Для поиска используйте `[deep-link]` и `[community-listing]`.

- `polling_starting` — бот начинает приём обновлений.
- `received` — получен `/start`; `update_id` связывает события одного перехода, `age_ms` показывает возраст сообщения к моменту обработки.
- `route` — маршрут: `listing`, `seller_request`, `invite`, `menu` или `unknown`. `menu` означает, что Telegram прислал `/start` без параметра.
- `registered` / `registered_existing` / `published` — регистрация и публикация лота на стороне гаранта.
- `lookup` — результат поиска; изменения статуса, номер попытки и прошедшее время.
- `preview_sent` — Telegram подтвердил отправку карточки.
- `handled` / `failed` — завершение обработки или ошибка; `elapsed_ms` показывает время работы обработчика.
- `activation_timeout` — предложка не активировала лот за 8 секунд. Тогда нужно проверить её публикацию/связь с API, а не считать лот проданным.

Для сопоставления лотов записываются только последние 6 символов токена; полный токен и текст объявления в эти логи не выводятся. Суффикс не является уникальным идентификатором.

## Проверка

Выполнены `npm run test:integration` и `npm run build`. Тесты используют локальную SQLite и подмену Telegram API: проверены первый `/start` во время активации, ожидание регистрации, таймаут, снятые/занятые лоты, продавец и закрытие предыдущего ввода. Отдельный тест подтверждает запуск polling при зависшей проверке TON и настройке меню.

Проверка в реальном Telegram/Railway необходима после развёртывания. Если после клика нет `received`, бот ещё не получил `/start`; если есть `preview_sent`, Telegram принял карточку. Изменение кода не может обеспечить доставку сообщения, которое Telegram не передал, или исправить другой экземпляр бота с отдельной базой.
