# Обновление гаранта — 2026-10-04_listing-notices-v3

Этот архив включает предыдущие исправления открытия ссылок и кнопки покупки, а также новые исправления уведомлений продавцу и проверки доступности лота.

## Как установить

Замените файлы из архива исправлений в корне проекта, сохранив пути. Добавьте новые файлы, которых раньше не было. Пересоберите и перезапустите автогаранта в Railway. В логах должно быть:

`OBRA BUILD: 2026-10-04_listing-notices-v3`

Базу `/data/escrow.sqlite` и постоянный том сохраните. Новая таблица уведомлений создаётся автоматически. Существующие неистёкшие неподтверждённые запросы подхватываются при запуске. Состояния существующих лотов обновление не меняет. Запускайте один polling-процесс для токена этого бота.

Предложку для этого исправления менять не требуется.

## Изменения

- Гарант сам отправляет продавцу запрос с кнопками «Подтвердить продажу» / «Отклонить запрос». Это больше не зависит от успешного цикла синхронизации предложки; её уведомление остаётся дополнительным каналом.
- Неудачные отправки сохраняются в SQLite и повторяются с интервалом не менее 15 секунд, пока запрос не истёк, не отклонён, не принят и лот активен. После перезапуска очередь сохраняется. Подтверждённые доставки повторно не отправляются. В случае потери ответа Telegram после фактической доставки или остановки процесса между отправкой и записью подтверждения возможен повтор уведомления; кнопки используют ту же сделку.
- Если продавец не запускал гаранта или заблокировал его, Telegram может отказать в личном сообщении. Продавцу нужно открыть гаранта и нажать `/start` / разблокировать его. Незавершённый запрос затем будет отправлен повторно, если ещё действует.
- Повторное нажатие покупателя на его уже подтверждённую бронь открывает ту же сделку. Повторный переход по ссылке объявления также показывает существующую сделку её участнику.
- «Недоступность» определяется только статусом лота в SQLite. Уведомление продавцу, задержка синхронизации и повторные нажатия сами по себе не меняют статус и не бронируют товар.
- Общий текст «Лот недоступен для покупки» заменён конкретной причиной. Покупателю больше не сообщается о гарантированной доставке продавцу до её подтверждения Telegram.

## Статусы лота

- `pending`: предложка ещё не завершила активацию публикации.
- `active`: доступен для новых запросов покупателей.
- `reserved`: продавец принял запрос; хранится ID закреплённой сделки. Этот покупатель может открыть свою сделку, остальные не могут купить тот же лот.
- `inactive`: объявление снято через API предложки либо отменена закреплённая подтверждённая сделка.
- `sold`: закреплённая сделка завершена.
- `review`: закреплённая сделка завершена через разрешение спора.

Отмена/истечение неподтверждённого запроса сами по себе не снимают активный лот. Если старый лот уже оказался `inactive`, обновление не активирует его автоматически: продавец должен проверить его актуальность и включить её через предложку. Зарезервированные/проданные лоты таким способом разблокировать нельзя.

## Логи Railway

- `[listing-buy] availability`: текущий `status`, `reserved_deal_id`, `existing_deal_id`. Эта строка объясняет причину отказа конкретному покупателю.
- `[community-listing] availability_changed`: изменение актуальности через API предложки, старый и новый статус.
- `[community-listing] reserved`: продавец принял запрос и закрепил сделку за лотом.
- `[listing-buy] request_saved`: запрос записан, есть `deal_id`.
- `[seller-notice] sending` / `delivered` / `delivery_failed`: попытка личного сообщения продавцу, подтверждение Telegram или причина ошибки. `delivered` означает принятие сообщения Telegram, а не прочтение продавцом.
- `[listing-buy] confirmation_sent`: Telegram принял подтверждение покупателю.
- `[deep-link] received` / `route` / `handled`: обработка ссылки.

Для диагностики сообщения со скриншота нужны логи `[listing-buy]` в момент нажатия и `[seller-notice]`. По одному скриншоту нельзя восстановить фактическое состояние базы или причину изменения статуса. Полные токены лотов и ключи интеграции в новые логи не выводятся.

## Проверено

Локальные интеграционные тесты: первый переход, ошибки/задержки ответа на кнопку, уведомление продавцу, повторное открытие собственной брони, запрет покупки чужой брони, истечение запросов без снятия лота, повторная доставка после сбоя/перезапуска и отсутствие повторных отправок после подтверждённой доставки. Выполнена production-сборка. Реальную доставку в Telegram нужно проверить после деплоя.
