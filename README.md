# OBRA GUARANT — Telegram Escrow + Mini App

Telegram-бот и встроенный Mini App. Каждая сделка использует отдельный escrow-смарт-контракт.
Требуется Node.js 22 или новее. База использует встроенный `node:sqlite`, поэтому
Visual Studio Build Tools и Python для установки не нужны.

## Как работает сделка

1. Покупатель или продавец нажимает **«Новая сделка»**.
2. Указывает роль, вторую сторону, сумму в TON и предмет сделки.
3. Вторая сторона присоединяется по уникальной ссылке.
4. Оба участника сохраняют свои TON-адреса через меню **«Кошелёк»**.
5. Бот разворачивает отдельный контракт и сообщает его адрес.
6. Покупатель переводит точную сумму TON одной транзакцией без комментария.
7. После появления депозита продавец передаёт товар или оказывает услугу.
8. Покупатель дважды подтверждает получение.
9. Контракт отправляет продавцу сумму за вычетом комиссии, а комиссию — на
   `PLATFORM_ADDRESS`.

До оплаты любой участник может отменить сделку. Если контракт уже создан, бот
сначала перепроверяет его on-chain состояние. После оплаты односторонняя отмена
запрещена: участник открывает спор, а арбитр выбирает возврат или распределение.

## Какой кошелёк использует бот

Бот **не генерирует кошелёк при запуске**. Он всегда берёт ровно 24 слова из
`ARBITER_MNEMONIC` и открывает соответствующий `Wallet V4`. На старте выводится
фактический адрес `Service wallet` — сверяйте и пополняйте именно его.

Служебный кошелёк оплачивает газ и подписывает действия арбитра. Депозиты
пользователей находятся не на нём, а на отдельных escrow-контрактах. Seed-фраза
даёт возможность вручную вызвать разрешённые контрактом `Confirm`, `Cancel` или
`Resolve`, но не позволяет заменить адреса получателей внутри уже созданной сделки.

Некоторые приложения при импорте той же seed-фразы по умолчанию показывают Wallet
V5, то есть другой адрес. Для аварийного управления надёжнее использовать CLI из
этого проекта; он открывает тот же V4, что и бот.

## Установка и настройка

```bash
npm install
copy .env.example .env
```

`npm run wallet:new` нужен только если требуется создать новый отдельный
служебный кошелёк. Если кошелёк уже есть, эту команду запускать не нужно.

Основные параметры `.env`:

- `BOT_TOKEN` — токен от BotFather;
- `ARBITER_TG_IDS` — Telegram ID администраторов через запятую;
- `ARBITER_MNEMONIC` — 24 слова отдельного служебного Wallet V4;
- `EXPECTED_SERVICE_WALLET_ADDRESS` — ожидаемый V4-адрес; при несовпадении с
  seed-фразой запуск останавливается (настоятельно рекомендуется);
- `PLATFORM_ADDRESS` — адрес получения комиссии;
- `TON_NETWORK=mainnet` и mainnet `TON_ENDPOINT`;
- `MIN_DEAL_TON`, `MAX_DEAL_TON` — разрешённый диапазон сумм;
- `MAX_ACTIVE_DEALS_PER_USER` — защита от массового создания сделок;
- `DB_PATH=./data/escrow-mainnet.sqlite` — отдельная mainnet-база.
- `MINI_APP_URL` — публичный HTTPS-адрес Mini App без `/` в конце; до появления
  домена его можно оставить пустым;
- `MINI_APP_PORT=3000` — локальный порт HTTP-сервера, который нужно проксировать
  через Nginx/Caddy;
- `SUPPORT_USERNAME=admssupport_bot` — контакт поддержки без `@`.

Не смешивайте testnet и mainnet в одном SQLite-файле. Секреты не должны попадать
в Git, переписку или публичный архив.

## Проверка и запуск

```bash
npm run build:contract
npm run typecheck
npm test
npm run dev
```

Production:

```bash
npm run build
npm start
```

На старте должны появиться `TON network: mainnet`, mainnet RPC, адрес и баланс
служебного кошелька, `Mini App server: ...`, затем `Escrow bot started as ...`.

## Mini App

Mini App находится в каталоге `miniapp/` и не требует React/Vite или отдельного
frontend-процесса. Тот же Node.js процесс раздаёт HTML/CSS/JS и защищённый API,
использующий ту же SQLite-базу.

Реализованы:

- главная, профиль, список и карточка сделки;
- создание сделки и одноразовое приглашение второй стороны;
- сохранение TON-адреса;
- оплата escrow через TON Connect с проверкой, что подключён сохранённый кошелёк
  покупателя;
- подтверждение получения, отмена до оплаты и спор после оплаты;
- on-chain данные, Tonviewer/Tonscan, комиссия и hash кода контракта;
- админ-режим для ID из `ARBITER_TG_IDS`: статистика, возврат и распределение
  средств при споре.

Без домена можно проверить только внешний вид в браузере:

```text
http://localhost:3000
```

Данные и действия там намеренно закрыты: backend принимает только подписанный
Telegram `initData`. Для полноценной проверки нужен публичный HTTPS URL. После
настройки домена задайте, например:

```env
MINI_APP_URL=https://app.example.com
MINI_APP_PORT=3000
SUPPORT_USERNAME=admssupport_bot
```

Перезапустите процесс. Бот сам установит кнопку меню **«Открыть OBRA GUARANT»**,
а постоянная клавиатура получит кнопку Mini App. URL также нужно зарегистрировать
в BotFather при создании Mini App. `tonconnect-manifest.json` формируется
автоматически по `MINI_APP_URL`.

На VPS не открывайте порт 3000 в интернет напрямую. Публичными должны быть только
80/443; Nginx или Caddy завершает HTTPS и проксирует запросы на
`127.0.0.1:3000`. Для health-check доступен `/health`.

### Где менять визуал

- `miniapp/index.html` — оболочка страницы;
- `miniapp/styles.css` — палитра и компоненты (`--blue: #004EA3`);
- `miniapp/app.js` — экраны и тексты Mini App;
- `miniapp/logo.png` — временный логотип;
- `src/miniapp.ts` — авторизация Telegram и API; менять его нужно осторожно.

Сервер не доверяет `initDataUnsafe`: он перепроверяет HMAC-подпись, срок сессии,
Telegram ID и права участника на каждое действие. POST-запросы ограничены по
частоте, тело запроса — по размеру. Seed-фраза никогда не передаётся frontend.

## Команды и интерфейс

Bot API автоматически получает всплывающее меню команд. Основные действия также
доступны в постоянной клавиатуре:

- `/newdeal` — создать сделку;
- `/mydeals` — карточки последних сделок с кнопками;
- `/wallet` — показать или заменить адрес участника;
- `/status <id>` — открыть карточку сделки;
- `/canceldeal <id>` — отменить неоплаченную сделку;
- `/transparency` — сеть, комиссия, служебный кошелёк, отпечаток кода контракта
  и ссылки на обозреватели;
- `/stop` — закрыть текущий пошаговый ввод;
- `/help` — памятка пользователю.

Администратору из `ARBITER_TG_IDS` после `/start` доступна кнопка
**«Админ-панель»** и команда `/admin`. Панель показывает статистику, споры,
оплаченные сделки, незавершённые blockchain-операции, последние сделки и баланс
служебного кошелька. Из карточки сделки доступны безопасные быстрые действия с
повторным подтверждением. Команды `/cancel <id>` и `/resolve <id> <% продавцу>`
остаются для произвольного процента решения спора.

## Публичная прозрачность

- В сообщении о развёртывании и карточке сделки есть прямые ссылки на Tonviewer
- Покупателю приходят кнопки **«Tonkeeper»** и **«MyTonWallet»**. Первая
  использует стандартный TON transfer URI, вторая — официальный HTTPS-формат
  MyTonWallet. Обе передают адрес escrow и точную сумму в nanotons. Комментарий
  намеренно не передаётся: контракт принимает обычный перевод без комментария.
  Если ссылка не открылась на конкретном устройстве/клиенте Telegram, оплату
  нужно выполнить вручную по адресу из карточки сделки.
- Кнопки `@wallet` и `@cryptobot` не добавлены: для внешнего escrow-контракта
  у них нет документированного прямого invoice-формата с адресом и суммой.
  Crypto Pay invoice зачисляет средства во внутренний баланс CryptoBot, а
  контракт принимает депозит только от сохранённого buyer-адреса. Их безопасно
  подключать позже через Mini App и TON Connect, а не имитацией кнопки оплаты.

## Внешний вид и тексты

- `src/bot.ts` — весь интерфейс Telegram: тексты сообщений, сценарии,
  постоянное меню, inline-кнопки и карточки сделок.
- `src/emoji.ts` — Premium Custom Emoji ID, используемые в кнопках. Меняйте
  только строки ID; это должен быть `custom_emoji_id`, а не `file_id`.
- Адрес escrow в карточке сделки и сообщении о готовности контракта выводится
  как `<code>...</code>`, поэтому его удобно копировать в Telegram.
- Чтобы прикрепить фото, используйте в нужном месте `ctx.replyWithPhoto(...)`
  вместо `ctx.reply(...)`; в `caption` можно передать текст и тот же
  `reply_markup` с inline-кнопками.
  и Tonscan; Telegram может показать предпросмотр первой ссылки.
- `/transparency` публикует сеть, фактическую комиссию, адрес служебного Wallet
  V4, адрес комиссии и hash кода escrow-контракта.
- Hash позволяет сравнивать версию кода разных сделок и закрепить ожидаемое
  значение в публичном канале проекта.
- Бот честно сообщает, что текущая версия не проходила независимый аудит.
- Backend может оставаться закрытым, но для максимального доверия рекомендуется
  позднее отдельно опубликовать только контракт, его тесты и ожидаемый code hash.

## Аварийное управление

Сначала остановите обычный процесс бота, чтобы две операции не использовали один
и тот же seqno служебного кошелька. Затем проверьте состояние:

```bash
npm run admin -- status 123
```

Только после проверки отправляйте действие; флаг `--yes` обязателен:

```bash
npm run admin -- confirm 123 --yes
npm run admin -- cancel 123 --yes
npm run admin -- resolve 123 50 --yes
```

Если SQLite потерян, но сохранены ID сделки и адрес контракта:

```bash
npm run admin -- status-address EQ...
npm run admin -- cancel-address 123 EQ... --yes
```

CLI намеренно не принимает произвольный адрес выплаты. Деньги могут уйти только
покупателю, продавцу и платформе, записанным в контракте.

## Резервные копии и безопасность

- Храните seed-фразу офлайн и отдельную зашифрованную резервную копию `.env`.
- Регулярно копируйте `data/escrow-mainnet.sqlite` вместе с файлами `-wal` и `-shm`;
  безопаснее делать это при остановленном боте.
- Не запускайте одновременно две копии бота с одной БД и одной seed-фразой.
- Держите на служебном кошельке небольшой газовый баланс, не пользовательские
  средства.
- Адреса покупателя и продавца не могут совпадать.
- Сумма принимается только от зарегистрированного адреса покупателя и только
  точной одной транзакцией.
- Перед выплатой покупатель видит отдельное необратимое подтверждение.
- Финальный статус берётся из блокчейна, watcher восстанавливает зависшие операции.
- `.env`, SQLite, `node_modules` и временная сборка контракта не входят в архив.

Это mainnet-capable MVP, а не результат независимого security-аудита. До открытия
существенных лимитов закажите аудит контракта и серверной части, настройте
мониторинг/алерты и проверьте восстановление из резервной копии на отдельной машине.
